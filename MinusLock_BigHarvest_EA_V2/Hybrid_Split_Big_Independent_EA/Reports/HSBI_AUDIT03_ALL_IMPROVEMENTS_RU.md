## HSBI-A03-IMP-016 — Версионированные snapshot time windows

**Категория/тип:** BROKER_MODEL; Уточнение нормативного контракта. **Статус:** PROPOSAL_ONLY. **Приоритет:** MEDIUM. **Сложность:** LOW. **Owner approval:** REQUIRED.

**Связанные ограничения:** HSBI-A03-ERR-024 в [центральном реестре](HSBI_AUDIT03_ALL_ERRORS_RU.md). Эти карточки содержат текущие выражения, источники и контрпримеры.

**Модель и обоснование:** `0<=now-ts+acceptedSkew and age<=limit with explicit clock authority`. Зафиксировать clock source, допустимый future skew, costs/market/risk revision coherence. Timestamp freshness сама по себе не связывает content.

**Преимущество:** устранение конкретного недоказанного преобразования/предиката, указанного выше, с проверяемой областью ответственности. **Риски и совместимость:** Provider clock/skew contract. Предложение не является разрешением на one-file или многофайловый production diff; совместимость старых API должна быть доказана отдельно, неизвестные legacy записи не допускаются как новые деньги.

**BUY/SELL:** денежные identity/ledger правила симметричны направлениям; цены закрытия BUY=Bid,SELL=Ask остаются направленными. Для geometry/prefix-предложений нужен отдельный зеркальный вывод, а не смена только имени роли. **Денежный баланс:** изменения accounting не создают прибыль; всякое перемещение сохраняет исходный ресурс. **Risk/margin:** применяются независимо, положительный локальный результат не заменяет account gate. **FSM:** результат проверки не коммитит state и не отправляет действие; обязательный caller и recovery-boundary задаются до подключения.

**Критерии будущего подтверждения:** Будущий timestamp вне окна и несогласованный snapshot отвергаются без выбора произвольного zero-skew. Исполнение этих проверок в текущем этапе запрещено; они перечислены как условия следующего отдельно разрешённого этапа.
