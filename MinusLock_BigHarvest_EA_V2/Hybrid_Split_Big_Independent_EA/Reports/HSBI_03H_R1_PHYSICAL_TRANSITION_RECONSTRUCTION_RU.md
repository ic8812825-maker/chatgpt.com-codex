## Главный вывод

Нормативная стратегия описывает последовательные физические переходы, но прочитанный production расчёт не воспроизводит полную физическую цепь. При SmallTransition старую Far ликвидируют полностью. Новая Far — остаток ДРУГОЙ позиции, исходного BIG_CORE. У неё направление исходного Core, его цена открытия и тот же identifier/ticket. Поэтому FarClosed=F, CoreClosed=C−N, NewFar=N; F−N — сжатие стратегии, а не закрытый объём Far. Реальные tickets, fills, цены и realized суммы этого исполнения UNAVAILABLE: на этапе нет broker history и торговые операции запрещены.

## Как возникает минусовый замок

Docs09 задаёт BUY, подтверждение fill, SELL, подтверждение fill, затем закрытие INITIAL_PLUS после trigger. До этого есть двусторонний lock; после закрытия прибыльной leg остаётся одна убыточная позиция FAR. Initial Profit исключён из recovery/budgets по сохранённому D06 A; отрицательные факты/rollback/costs остаются в экономике. Сама смена роли не открывает сделку и не создаёт PnL.

Для Far SELL C/T направлены BUY, Small SELL; для Far BUY всё зеркально (Docs04). Объёмы C=floor(F Rc), T=floor(F Rt), S=ceil(F Rs), Bnet=C+T−S. Это размеры разных позиций. Trend и Core не один неразличимый BIG: у каждого собственные identity, cost facts и закрываемый объём. Geometry не доказывает fills.

Ветка BigHarvest имеет приоритет FinalClose перед PartialFar (Docs10). Docs10 и BigHarvestTypes не определяют однозначно полный набор и доли закрываемых C/T/S для каждого Harvest. Нельзя восстановить такие доли из имени BigHarvest. Они UNAVAILABLE до immutable HarvestPlan/fills. PartialFar по Docs11 уменьшает ту же Far, сохраняя identifier; это отдельная операция, не promotion.

Для RoleChange ActionVolume=0, это не торговый запрос.

Price basis: открыть BUY по actual Ask/fill, SELL по actual Bid/fill; закрыть BUY по Bid/fill, SELL по Ask/fill. Projected wrapper использует OrderCalcProfit на close-side; actual slippage уже в fill price. Net residual нельзя оценивать по цене открытия новой basket вместо inherited Core open. Unknown broker commission allocation на partial close нельзя молча пропорционировать; синтетический proportional cost допускается лишь в отдельно объявленной модели.

## Подтверждение каждого физического шага

Перед SMALL-k: immutable persisted plan, fresh trigger/revalidation, четыре caps, ownership, no active transition. После каждой close Action ожидаются ВСЕ actual closing deals. DONE_PARTIAL/timeout/unknown не разрешает следующий шаг. После Core close читается actual residual original identifier; requested N не evidence. Должны остаться ровно один managed position и ни одной old Far/Small/Trend. При mismatch → reconciliation/terminal safe, без auto-resume.

Внутри перехода после удаления old Far и до promotion формально нет роли FAR; это защищённый executing state, не разрешение открыть следующую basket. Инвариант «один Far» относится к устойчивому reconciled состоянию; префиксы требуют transaction barrier. Преждевременная role change создала бы две Far либо скрыла незакрытую old Far.

## Денежные следствия физического membership

Для SmallTransition:
ProjectedClosingNet = SmallCloseNet(S)+OldFarCloseNet(F)+TrendCloseNet(T)+CoreCloseNet(C−N).
ProjectedPhysicalTransitionLoss=max(0,−ProjectedClosingNet).
ResidualOpenNet=CoreResidualNet(N).
При одном линейном cost basis ClosingNet+ResidualNet = full basket close-now net; при нелинейных/минимальных fees это равенство требует отдельной проверки. ActualTransitionLoss всегда из actual closing deals, не full-basket preview.

Basket evaluator считает full Core C. Поэтому его max(0,−basketNet) — loss ликвидации всей оценённой basket, не доказанный actual SmallTransitionLoss, если N>0. При синтетических примерах следующего отчёта basket loss4000, physical closing loss3600, open residual−400. Полный Core profit нельзя распределить как cash, оставив часть его нереализованной. Allocation — использование уже учтённого дохода, не новый доход и не второе списание в CyclePnL.
