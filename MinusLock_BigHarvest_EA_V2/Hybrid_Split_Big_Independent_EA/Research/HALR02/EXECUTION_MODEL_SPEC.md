# Execution Simulator

Единица времени — одно наблюдаемое событие. Сначала видна новая котировка и начисляется carry. Затем обслуживаются активные заявки. Контроллер получает фактически обновлённый журнал и может подать новые поручения. Capacity общий для всех fill текущего события. Reject относится к очередным новым заявкам события. Delay задаёт минимальное время до первого fill заявки. Цена fill — котировка события исполнения.

Автомат фиксирует CREATED, SUBMITTED, ACCEPTED, PARTIAL, FILLED, REJECTED, CANCEL_PENDING, CANCELLED, EXPIRED и UNKNOWN. При отмене есть минимум одно событие до подтверждения. В cancel_race допустим fill перед подтверждением. UNKNOWN удерживает остаток в модели заявок. Такой ордер может быть подтверждён или истечь. Повтор с тем же client key возвращает старый ордер, отличный key создаёт отдельное поручение. Позиции меняет только подтверждённый fill. Журнал хранит котировку, действия, изменения состояния и параметры каждого fill.

Номинальный контракт допускает исполнение всех последовательных заявок на одной котировке. Сбойный контракт проверяется отдельно. Режим отсутствия ликвидности на всём горизонте исключает гарантированную ликвидацию даже для K-EXECUTABLE.
