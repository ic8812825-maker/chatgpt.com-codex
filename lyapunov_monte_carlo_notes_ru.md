# Lyapunov и Monte Carlo в Adaptive EV

## Ответ на вопрос «Есть ли Lyapunov и Monte Carlo?»
- **Ранее в проекте их не было как отдельного формального слоя.**
- В этом обновлении добавлен отдельный расчетный скрипт:
  - `lyapunov_monte_carlo_assessment.py`
  - результат: `lyapunov_monte_carlo_results.json`

## Что реализовано

### 1) Monte Carlo
- 200 случайных прогонов параметров (`alpha`, `delta_step`, `gamma`, `ls_min`) по 5 рыночным сценариям.
- Для каждого сценария считаются:
  - `pass_rate`
  - `avg_equity`
  - `p05_equity` (консервативная нижняя оценка).

### 2) Lyapunov-proxy
- Используется практический прокси, а не строгий непрерывный показатель:
  - функционал риска: `R = max_drawdown + 0.5*survival_violations + max(0, -equity)`
  - `lambda_proxy = E[log((R_pert+eps)/(R_base+eps))]`
- Интерпретация:
  - `lambda_proxy < 0` → локально «сжимающее» поведение,
  - `lambda_proxy > 0` → чувствительность к возмущениям выше (нужны дополнительные ограничения).

## Краткий вывод по текущему прогону
- В части сценариев proxy отрицательный (хорошо), но в `TREND_UP_MODERATE` и особенно `SHOCK_REGIME` proxy положительный.
- Это означает: для шоковых режимов стоит усилить risk-first блоки (`ESCAPE`, лимит на новые циклы, фильтр spread/volatility).

## Практические рекомендации внедрения
1. Включить метрики Monte Carlo и Lyapunov-proxy в обязательный pre-release отчет.
2. Установить пороги приемки:
   - `pass_rate >= 0.70` для каждого сценария,
   - `p05_equity >= 0` для базового релиза,
   - `lambda_proxy <= 0` для всех сценариев, либо явный список исключений и компенсирующих ограничений.
3. Если `lambda_proxy > 0` в SHOCK-режиме:
   - снижать `k_max`,
   - ужесточать `Emax`,
   - раньше переводить FSM в `STRESS/ESCAPE`.
