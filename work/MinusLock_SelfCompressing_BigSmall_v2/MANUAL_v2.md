# Полный мануал: Адаптивная Самосжимающаяся Система Разруливания Минусового Замка

> **Важно:** документ описывает механику торговой системы и правила контроля риска. Это не инвестиционная рекомендация и не гарантия прибыли. Любая локирующая, хеджирующая или сеточная логика может привести к полной потере депозита при разрывах цены, расширении спреда, нехватке маржи, проскальзывании, ошибках исполнения и неверной оценке волатильности.

---

## 1. Назначение системы

Адаптивная самосжимающаяся система разруливания минусового замка предназначена для контролируемой работы с ситуацией, когда после локирования одна сторона замка была закрыта в прибыль, а вторая осталась в минусе и стала дальним хвостом.

Главная цель системы — не максимизация прибыли, а **плановое уменьшение минусового хвоста, снижение маржинальной нагрузки и накопление резерва** через повторяемые рабочие циклы.

Система должна стремиться к четырём результатам в каждом завершённом цикле:

1. уменьшить дальний хвост;
2. уменьшить будущую маржинальную нагрузку;
3. увеличить денежный резерв;
4. снизить общий риск следующего цикла.

Система не должна превращаться в:

- мартингейл;
- удвоение объёма;
- бесконечную сетку;
- хаотическое усреднение;
- накопление разнонаправленных незакрытых слоёв.

---

## 2. Базовая идея

Стартовая ситуация:

```text
BUY = SELL
```

После движения цены одна сторона закрывается в прибыль, а вторая остаётся отрицательной. Оставшаяся минусовая позиция называется **дальним хвостом** или **Far Start**.

Далее система строит новый рабочий уровень:

- **Big** — основная позиция по текущему рабочему направлению;
- **Small** — встречная защитная позиция;
- **Reserve** — часть реализованной прибыли, которая не расходуется на хвост, а накапливается как буфер;
- **Far Start** — самый дальний минусовой остаток, который требуется уменьшать.

Ключевая логика:

- если цена идёт в сторону Big, Big зарабатывает, Small закрывается с ограниченным минусом, а часть чистой прибыли направляется на уменьшение хвоста;
- если цена идёт в сторону Small, Small зарабатывает, Big частично закрывается, остаток Big становится новым хвостом меньшего размера, и система переворачивается.

---

## 3. Термины и обозначения

| Термин | Обозначение | Смысл |
| --- | ---: | --- |
| Far Start / дальний хвост | `F_n` | Самая дальняя минусовая позиция текущего цикла. |
| Big | `B_n` | Основная рабочая позиция уровня, открываемая по рабочему направлению. |
| Small | `S_n` | Встречная защитная позиция уровня. |
| Reserve | `R_n` | Накопленная часть реализованной чистой прибыли. |
| Net | `N_n` | Чистый направленный перевес между Big и хвостом. |
| NetProfit | `NP_n` | Чистая прибыль завершённого уровня после учёта плюсов, минусов, комиссии и спреда. |
| CloseFar | `CF_n` | Денежная или лотовая часть, направленная на уменьшение дальнего хвоста. |
| CloseBig | `CB_n` | Часть Big, закрываемая при Small-сценарии. |
| RemainBig | `RB_n` | Остаток Big после частичного закрытия, становящийся новым хвостом. |

Индекс `n` означает номер текущего цикла.

---

## 4. Канонические параметры системы

| Параметр | Формула / значение | Назначение |
| --- | ---: | --- |
| Big | `B_n = F_n × 1.15` | Дать системе небольшой перевес в сторону рабочего движения. |
| Small | `S_n = B_n × 0.38` | Создать защиту от отката и механизм переворота. |
| Закрытие хвоста в Big-сценарии | `20%` | Уменьшать хвост, но не уничтожать резерв. |
| Резерв в Big-сценарии | `80%` | Накопить буфер для флэта, спреда, комиссий и ошибок исполнения. |
| Закрытие Big в Small-сценарии | `22%` | Сжать новый хвост даже при развороте. |
| Остаток Big | `78%` | Новый хвост после переворота. |

Допустимые технические границы:

| Параметр | Нормальный диапазон | Жёсткий запрет |
| --- | ---: | ---: |
| Big / Far | `1.10–1.20` | Не выше `1.20` без отдельного стресс-теста. |
| Small / Big | `0.30–0.45` | Не выше `0.45`. |
| Закрытие Big при перевороте | `0.20–0.30` | Не ниже `0.20`. |
| Доля прибыли на хвост | `0.10–0.25` | Не повышать, если резерв мал. |

Каноническая конфигурация системы:

```text
BigRatio        = 1.15
SmallRatio      = 0.38
FarCloseShare   = 0.20
ReserveShare    = 0.80
BigCloseOnFlip  = 0.22
BigRemainOnFlip = 0.78
```

## 5. Почему Big равен 115% от хвоста

Формула:

```text
B_n = F_n × 1.15
```

При хвосте `1.00` лот Big равен:

```text
B_1 = 1.00 × 1.15 = 1.15
```

Смысл коэффициента `1.15`:

- Big немного сильнее хвоста;
- система получает направленный перевес;
- перевес не становится агрессивным;
- маржа растёт умеренно;
- следующий цикл остаётся управляемым.

Чистый направленный перевес:

```text
Net = Big - FarStart
Net = 1.15 - 1.00 = 0.15
```

То есть система не пытается перекрыть минус грубой силой. Она создаёт только небольшой дополнительный импульс, достаточный для постепенного восстановления.

---

## 6. Почему Small равен 38% от Big

Формула:

```text
S_n = B_n × 0.38
```

При Big `1.15`:

```text
S_1 = 1.15 × 0.38 = 0.437 ≈ 0.44
```

Назначение Small:

- защитить уровень от отката;
- дать прибыль при развороте;
- запустить автоматический переворот системы;
- не дать Big зависнуть в полном объёме;
- не накапливаться как отдельный хвост.

Почему Small нельзя делать слишком маленьким:

- он не сможет компенсировать разворот;
- переворот будет слабым;
- новый хвост может перестать сжиматься.

Почему Small нельзя делать слишком большим:

- возрастёт маржа;
- откат против Small станет дорогим;
- Big-сценарий будет отдавать слишком много прибыли на закрытие Small;
- система начнёт работать как тяжёлый многослойный лок.

## 7. Стартовый пример

### 7.1. Начальный замок

Открыты две равные позиции:

| Позиция | Лот |
| --- | ---: |
| BUY | 1.00 |
| SELL | 1.00 |

Цена пошла вверх. BUY закрыт в прибыль. SELL остался в минусе.

Новый дальний хвост:

```text
F_1 = 1.00 SELL
```

### 7.2. Построение первого уровня

Big:

```text
B_1 = F_1 × 1.15 = 1.00 × 1.15 = 1.15 BUY
```

Small:

```text
S_1 = B_1 × 0.38 = 1.15 × 0.38 = 0.437 ≈ 0.44 SELL
```

Структура уровня:

| Элемент | Направление | Лот |
| --- | --- | ---: |
| Дальний хвост | SELL | 1.00 |
| Big | BUY | 1.15 |
| Small | SELL | 0.44 |

Суммарный открытый объём:

```text
TotalLots = 1.00 + 1.15 + 0.44 = 2.59
```

## 8. Два рабочих сценария

После построения уровня возможны только два штатных сценария.

### Сценарий A — цена идёт в сторону Big

Для хвоста SELL это движение вверх, потому что Big открыт BUY.

Результат:

- Big получает прибыль;
- Small получает минус;
- дальний хвост остаётся отрицательным;
- уровень закрывается полностью;
- часть чистой прибыли направляется на уменьшение хвоста;
- остальное уходит в резерв.

### Сценарий B — цена идёт в сторону Small

Для хвоста SELL это движение вниз, потому что Small открыт SELL.

Результат:

- Small получает прибыль;
- Big получает минус;
- Big закрывается частично;
- остаток Big становится новым хвостом;
- направление системы переворачивается;
- Small не накапливается.

---

## 9. Сценарий A: цена идёт в сторону Big

### 9.1. Обязательное правило закрытия уровня

Если цена дошла до цели Big-сценария, закрываются:

```text
Big   = 100%
Small = 100%
```

Small нельзя оставлять открытым.

Причины:

- Small начнут накапливаться;
- маржинальная нагрузка станет неконтролируемой;
- флэт превратится в серию разнонаправленных зависших позиций;
- система потеряет свойство самосжатия;
- вместо цикла появится многослойный лок.

Правило:

> Каждый рабочий уровень должен завершаться полностью. После Big-сценария не должно оставаться ни Big, ни Small текущего уровня.

### 9.2. Расчёт чистой прибыли уровня

Базовая формула:

```text
NetProfit = ProfitBig - LossSmall - Commission - SpreadCost - SlippageCost
```

Упрощённая формула без издержек:

```text
NetProfit = ProfitBig - LossSmall
```

Пример:

```text
ProfitBig = +200
LossSmall = -60
Commission + SpreadCost = 10
NetProfit = 200 - 60 - 10 = 130
```

Если издержки не учитывать:

```text
NetProfit = 200 - 60 = 140
```

В реальной системе издержки обязательно учитываются, потому что они напрямую уменьшают резерв и способность закрывать хвост.

### 9.3. Распределение прибыли

Каноническое распределение:

```text
CloseFarMoney = NetProfit × 0.20
ReserveAdd    = NetProfit × 0.80
```

Пример при `NetProfit = 140`:

```text
CloseFarMoney = 140 × 0.20 = 28
ReserveAdd    = 140 × 0.80 = 112
```

### 9.4. Важное различие: деньги и лоты

Формула `F_{n+1} = F_n × 0.80` корректна только если система действительно закрывает **20% лотового объёма хвоста**.

На практике чистая прибыль измеряется в деньгах, а хвост — в лотах. Поэтому нужен перевод:

```text
CloseFarLots = CloseFarMoney / LossPerLotToClose
F_{n+1}      = F_n - CloseFarLots
```

Где `LossPerLotToClose` — текущий денежный убыток на 1 лот хвоста, который нужно зафиксировать при частичном закрытии.

Если цель задана именно как лотовое сжатие на 20%, то используется:

```text
TargetCloseFarLots = F_n × 0.20
RequiredMoney      = TargetCloseFarLots × LossPerLotToClose
```

Далее проверяется:

```text
если NetProfit × 0.20 >= RequiredMoney:
    закрыть 20% хвоста по лоту
иначе:
    закрыть только доступный объём по деньгам
```

Таким образом, есть два режима:

| Режим | Что фиксировано | Что получается на выходе |
| --- | --- | --- |
| Денежный | 20% чистой прибыли | Закрывается столько лотов, сколько позволяет прибыль. |
| Лотовый | 20% хвоста | Требуется достаточная прибыль для оплаты фиксации убытка. |

Для строгого самосжатия предпочтителен **лотовый режим**, но он требует проверки достаточности прибыли.

## 11. Сценарий B: цена идёт в сторону Small

### 11.1. Действия системы

При достижении цели Small-сценария выполняются действия:

1. Small закрывается полностью.
2. Big закрывается частично на 22%.
3. Остаток Big в 78% становится новым дальним хвостом.
4. Система пересчитывает новый Big и новый Small уже в противоположную сторону.

Формулы:

```text
CloseBigLots = Big × 0.22
RemainBig    = Big × 0.78
```

Новый хвост:

```text
F_{n+1} = RemainBig
```

Так как:

```text
Big = F_n × 1.15
```

то:

```text
F_{n+1} = F_n × 1.15 × 0.78 = F_n × 0.897
```

Это означает, что даже при развороте хвост уменьшается примерно на:

```text
1 - 0.897 = 0.103 = 10.3%
```

### 11.2. Пример переворота

Исходный хвост:

```text
F_1 = 1.00 SELL
```

Big:

```text
B_1 = 1.00 × 1.15 = 1.15 BUY
```

Small:

```text
S_1 = 1.15 × 0.38 = 0.44 SELL
```

Цена пошла вниз, в сторону Small.

Закрываем Small полностью:

```text
Small 0.44 SELL закрыт в прибыль
```

Закрываем 22% Big:

```text
CloseBig = 1.15 × 0.22 = 0.253 BUY
```

Остаток Big:

```text
RemainBig = 1.15 × 0.78 = 0.897 BUY
```

Новый хвост:

```text
F_2 = 0.897 BUY
```

Система перевернулась: раньше хвост был SELL, теперь хвост стал BUY.

| Цикл | Старый хвост | Big = хвост × 1.15 | Закрытие Big 22% | Новый хвост = Big × 0.78 |

| 1 | 1.000 | 1.150 | 0.253 | 0.897 |
| 2 | 0.897 | 1.032 | 0.227 | 0.805 |
| 3 | 0.805 | 0.926 | 0.204 | 0.722 |
| 4 | 0.722 | 0.830 | 0.183 | 0.647 |

| 7 | 0.520 | 0.598 | 0.132 | 0.467 |

Общая формула после `k` последовательных Small-сценариев:

```text
F_k = F_0 × 0.897^k
```

## 12. Обработка старого хвоста при перевороте

В Small-сценарии цена идёт в сторону Small, а Small обычно совпадает по направлению со старым хвостом. Поэтому старый хвост часто уменьшается по плавающему убытку или может выйти в безубыток/прибыль.

Перед объявлением остатка Big новым хвостом система должна выполнить проверку старого хвоста:

1. Если старый хвост можно закрыть в плюс или в ноль — закрыть полностью.
2. Если старый хвост можно закрыть частично за счёт прибыли Small и разрешённой доли резерва — закрыть разрешённую часть.
3. Если старый хвост остаётся отрицательным и не может быть безопасно закрыт — система не должна открывать новый полноценный уровень поверх двух дальних хвостов без отдельного аварийного режима.

Каноническое правило:

> В штатном Small-сценарии после переворота активным дальним хвостом должен остаться только остаток Big. Старый хвост должен быть закрыт, нейтрализован или явно переведён в аварийный режим наблюдения.

Это правило защищает систему от скрытого превращения в многослойный лок.

## 13. Резерв

### 13.1. Назначение резерва

Резерв нужен для:

- покрытия комиссии;
- покрытия спреда;
- покрытия отрицательного проскальзывания;
- переживания флэта;
- переживания серии быстрых разворотов;
- частичного закрытия старых хвостов;
- защиты депозита от каскадной маржинальной нагрузки;
- отказа от новых входов в опасном режиме.

### 13.2. Формула резерва

В Big-сценарии:

```text
Reserve_n = Reserve_{n-1} + NetProfit_n × 0.80
```

Если в Small-сценарии после закрытия Small и 22% Big остаётся положительный реализованный результат:

```text
FlipNet = ProfitSmall - LossClosedBig - Costs
```

Тогда консервативное правило:

```text
если FlipNet > 0:
    Reserve_n = Reserve_{n-1} + FlipNet × 0.50
    оставшиеся 50% можно направить на старый хвост или оставить в свободном балансе
если FlipNet <= 0:
    Reserve_n = Reserve_{n-1}
    новый цикл разрешён только при достаточной свободной марже
```

Более жёсткое правило для риск-контроля:

```text
Reserve_n никогда не уменьшается для открытия новых позиций.
Reserve используется только для закрытия риска, комиссий и аварийного выхода.
```

### 13.3. Минимальный резерв

Перед запуском очередного уровня резерв должен покрывать хотя бы:

```text
MinReserve = ExpectedSpreadCost + ExpectedCommission + EmergencySlippageBuffer
```

Практическая расширенная формула:

```text
MinReserve = 3 × AverageCycleCost + 1 × WorstNormalSlippage
```

Если резерв ниже минимума:

- новые уровни не открываются;
- разрешено только закрытие риска;
- система ждёт более выгодного выхода или ручного решения.

## 14. Маржа и нагрузка

Формула маржи:

```text
Margin = TotalLots × MarginPerLot
```

Где:

```text
TotalLots = FarLots + BigLots + SmallLots
```

Для первого уровня:

```text
TotalLots = 1.00 + 1.15 + 0.44 = 2.59
```

При условной марже `1000` на 1 лот:

```text
Margin = 2.59 × 1000 = 2590
```

После успешного сжатия хвоста маржа следующего уровня падает, потому что Big и Small считаются от меньшего `F_n`.

Пример при Big-сценариях:

| Цикл | Хвост | Big 115% | Small 38% от Big | TotalLots |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 1.000 | 1.150 | 0.437 | 2.587 |
| 2 | 0.800 | 0.920 | 0.350 | 2.070 |
| 3 | 0.640 | 0.736 | 0.280 | 1.656 |
| 4 | 0.512 | 0.589 | 0.224 | 1.325 |
| 5 | 0.410 | 0.471 | 0.179 | 1.060 |

Именно это является практическим самосжатием: каждый следующий уровень легче предыдущего.

## 15. Триггеры входа и выхода

### 15.1. Что должно быть определено заранее

Система не может работать только на формулах лотов. До запуска нужно определить:

- инструмент;
- минимальный шаг лота;
- стоимость пункта;
- средний спред;
- комиссию;
- допустимое проскальзывание;
- расстояние до Big-цели;
- расстояние до Small-цели;
- максимальную маржу;
- максимальную просадку;
- правила отключения.

### 15.2. Big-цель

Big-сценарий считается выполненным, когда прибыль Big достаточна, чтобы:

```text
ProfitBig >= LossSmall + Costs + RequiredCloseFarMoney + RequiredReserveAdd
```

В упрощённом виде:

```text
ProfitBig - LossSmall - Costs > 0
```

Но для качественного цикла этого мало. Хороший Big-выход должен давать:

- положительный NetProfit;
- закрытие запланированной доли хвоста;
- пополнение резерва;
- отсутствие незакрытого Small.

### 15.3. Small-цель

Small-сценарий считается выполненным, когда:

```text
ProfitSmall >= LossClosedBig + Costs
```

или когда риск дальнейшего удержания Big становится выше, чем цена немедленного переворота.

Минимальное действие при Small-сценарии:

```text
закрыть Small 100%
закрыть Big 22%
пересчитать новый хвост
```

## 16. Пошаговый алгоритм цикла

### 16.1. Инициализация

1. Найти текущий дальний хвост `F_n`.
2. Проверить, что открытие нового уровня не нарушит лимит маржи.
3. Проверить, что резерв не ниже минимального.
4. Рассчитать Big:

```text
B_n = F_n × 1.15
```

5. Рассчитать Small:

```text
S_n = B_n × 0.38
```

6. Округлить лоты по правилам брокера.
7. Открыть Big по рабочему направлению.
8. Открыть Small в противоположном направлении.

### 16.2. Мониторинг

На каждом тике или баре система проверяет:

- текущую прибыль Big;
- текущую прибыль Small;
- плавающий результат хвоста;
- свободную маржу;
- фактический спред;
- проскальзывание;
- лимиты риска;
- наступление Big-сценария;
- наступление Small-сценария.

### 16.3. Завершение по Big-сценарию

1. Закрыть Big полностью.
2. Закрыть Small полностью.
3. Посчитать NetProfit.
4. Если NetProfit <= 0, запретить распределение прибыли и перейти в диагностику.
5. Направить 20% NetProfit на хвост или закрыть 20% лотов хвоста при достаточности прибыли.
6. Направить 80% NetProfit в Reserve.
7. Пересчитать `F_{n+1}`.
8. Если хвост ниже минимального лота — закрыть остаток по правилам финализации.
9. Если хвост ещё существует — открыть следующий уровень меньшего размера.

### 16.4. Завершение по Small-сценарию

1. Закрыть Small полностью.
2. Закрыть 22% Big.
3. Посчитать результат переворота:

```text
FlipNet = ProfitSmall - LossClosedBig - Costs
```

4. Обработать старый хвост: закрыть, нейтрализовать или перевести в аварийный режим.
5. Остаток Big объявить новым хвостом:

```text
F_{n+1} = Big × 0.78
```

6. Перевернуть направление системы.
7. Проверить маржу и резерв.
8. Если лимиты в норме — построить следующий уровень от нового хвоста.

## 17. Псевдокод

```text
parameters:
    BigRatio        = 1.15
    SmallRatio      = 0.38
    FarCloseShare   = 0.20
    ReserveShare    = 0.80
    BigCloseOnFlip  = 0.22
    MaxBigRatio     = 1.20
    MaxSmallRatio   = 0.45

state:
    FarLots
    FarDirection
    Reserve
    CycleNumber

start_cycle:
    assert FarLots > 0
    assert Reserve >= MinReserve
    assert margin_after_new_level <= MaxAllowedMargin

    BigLots   = round_lot(FarLots * BigRatio)
    SmallLots = round_lot(BigLots * SmallRatio)

    BigDirection   = opposite(FarDirection)
    SmallDirection = FarDirection

    open(BigDirection, BigLots)
    open(SmallDirection, SmallLots)

monitor:
    while level_is_open:
        update_pnl()
        update_margin()
        update_spread()

        if hard_risk_limit_hit:
            go_to_emergency_mode()
            break

        if big_target_hit:
            close(Big, 100%)
            close(Small, 100%)
            NetProfit = ProfitBig - LossSmall - Costs

            if NetProfit > 0:
                CloseFarMoney = NetProfit * FarCloseShare
                Reserve += NetProfit * ReserveShare
                close_far_by_money_or_target_lots(CloseFarMoney)
            else:
                block_new_cycle_and_diagnose()

            recalc_far()
            break

        if small_target_hit:
            close(Small, 100%)
            close(Big, BigCloseOnFlip)
            FlipNet = ProfitSmall - LossClosedBig - Costs

            if FlipNet > 0:
                Reserve += FlipNet * 0.50

            process_old_far()
            FarLots = remaining(Big)
            FarDirection = BigDirection
            break
```

## 18. Округление лотов

Реальный рынок не всегда позволяет открыть `0.437` лота. Поэтому нужен модуль округления.

Правило:

```text
RoundedLot = round_to_broker_step(RawLot)
```

Если шаг лота `0.01`:

```text
0.437 → 0.44
```

Если шаг лота `0.10`:

```text
0.437 → 0.40 или 0.50
```

Консервативное правило:

- Big лучше округлять вниз, если маржа близка к лимиту;
- Small лучше округлять вниз, если он становится слишком тяжёлым;
- нельзя округлением нарушать запреты `Big > 120%` и `Small > 45%`.

После округления обязательно пересчитать фактические коэффициенты:

```text
ActualBigRatio   = RoundedBig / FarLots
ActualSmallRatio = RoundedSmall / RoundedBig
```

Если фактические коэффициенты вышли за пределы, уровень не открывается.

## 19. Риск-лимиты

Перед каждым циклом должны проверяться лимиты.

### 19.1. Лимит маржи

```text
MarginAfterOpen <= MaxMarginUsage
```

Рекомендуемое правило:

```text
UsedMargin / Equity <= 0.30–0.50
```

Чем выше волатильность и хуже исполнение, тем ниже должен быть лимит.

### 19.2. Лимит просадки

```text
FloatingDrawdown / Equity <= MaxDrawdown
```

Если лимит превышен:

- новые уровни запрещены;
- допускается только уменьшение риска;
- система переходит в аварийный режим.

### 19.3. Лимит спреда

```text
CurrentSpread <= MaxAllowedSpread
```

Если спред расширился:

- новые входы запрещены;
- рыночные закрытия выполняются только при угрозе большего риска;
- предпочтительно ждать нормализации спреда, если маржа позволяет.

### 19.4. Лимит количества циклов

Чтобы система не работала бесконечно во вредной среде:

```text
MaxCyclesPerSession = заранее заданное число
```

После достижения лимита:

- новые уровни не открываются;
- система фиксирует состояние;
- требуется ручная проверка или пауза.

## 20. Аварийные режимы

### 20.1. Margin Stress

Условие:

```text
FreeMargin падает ниже допустимого уровня
```

Действия:

- запретить новые уровни;
- закрывать только прибыльные защитные позиции;
- использовать резерв только для уменьшения хвоста;
- уменьшить BigRatio в следующих циклах;
- при критической угрозе закрывать риск по заранее заданному плану.

### 20.2. Spread Shock

Условие:

```text
Spread > MaxAllowedSpread
```

Действия:

- не открывать Big/Small;
- не закрывать плановые позиции без необходимости;
- пересчитать ожидаемую прибыль целей;
- включить паузу до нормализации.

### 20.3. Fast Reversal

Условие:

```text
Цена быстро проходит от Big-зоны к Small-зоне или наоборот
```

Действия:

- не добавлять дополнительные Small;
- выполнять только канонический переворот;
- проверять фактическое проскальзывание;
- после переворота уменьшить следующий объём или пропустить цикл.

### 20.4. Dual-Tail Exception

Условие:

```text
После переворота остался старый хвост и появился новый хвост
```

Действия:

- запретить открытие нового полного уровня;
- закрывать прибыльную сторону при первой возможности;
- использовать резерв только для сокращения одного из хвостов;
- восстановить состояние с одним активным Far Start.

## 21. Как система переживает флэт

Во флэте цена может часто переходить из Big-зоны в Small-зону и обратно.

Система выживает во флэте только при соблюдении правил:

- Small всегда закрывается полностью;
- Big при Small-сценарии закрывается минимум на 22%;
- новый хвост после переворота меньше старого;
- резерв не расходуется на усиление позиций;
- новые уровни открываются только после закрытия предыдущего уровня;
- при ухудшении спреда система ставится на паузу.

Опасность флэта:

- много комиссий;
- много спреда;
- ложные срабатывания целей;
- проскальзывание;
- появление двух хвостов при неправильной обработке старого.

Поэтому во флэте особенно важно соблюдать запрет на накопление Small.

---

## 22. Как система переживает сильный тренд

В сильном тренде Big-сценарий должен происходить быстрее.

Положительный эффект тренда:

- Big быстро набирает прибыль;
- Small имеет ограниченный минус;
- уровень закрывается полностью;
- хвост уменьшается;
- резерв растёт;
- следующий уровень становится легче.

Главная опасность тренда:

- если хвост направлен против тренда, его плавающий минус растёт;
- если Big-цель слишком далека, цена может дать резкий откат до Small;
- если Small не закрыт, система начнёт копить встречные слои.

Правило:

> В тренде нельзя жадничать. Big-сценарий должен закрывать уровень, а не превращаться в удержание ради максимальной прибыли.

## 23. Финализация системы

Система считается успешно завершённой, если:

```text
FarLots <= MinLot
```

или если денежный убыток хвоста можно полностью покрыть разрешённой частью прибыли и резерва без нарушения лимитов.

Финальные действия:

1. Закрыть остаток дальнего хвоста.
2. Закрыть все рабочие Big/Small, если они есть.
3. Зафиксировать итоговый резерв.
4. Составить отчёт по циклам.
5. Запретить автоматический перезапуск без новой причины.

Итоговый отчёт должен содержать:

- количество циклов;
- максимальный открытый объём;
- максимальную маржу;
- максимальную просадку;
- суммарную прибыль Big;
- суммарную прибыль Small;
- суммарные убытки частичных закрытий;
- суммарные комиссии и спред;
- размер уничтоженного хвоста;
- итоговый резерв.

## 24. Что строго запрещено

Запрещено:

1. Делать Big больше 120% от хвоста без отдельного расчёта риска.
2. Делать Small больше 45% от Big.
3. Оставлять Small после завершения уровня.
4. Открывать новый уровень, если предыдущий не завершён.
5. Использовать резерв для увеличения объёма.
6. Закрывать меньше 20% Big при Small-сценарии.
7. Игнорировать комиссии, спред и проскальзывание.
8. Считать денежные 20% прибыли равными лотовым 20% хвоста без пересчёта.
9. Открывать новый цикл при недостаточной свободной марже.
10. Продолжать автоматическую работу при появлении двух дальних хвостов без аварийного режима.

## 27. Уточнения v2: недвусмысленные правила исполнения

Этот раздел является обязательным уточнением к предыдущим формулам и имеет приоритет при практической реализации калькулятора или торгового робота.

### 27.1. Главное правило Big-сценария

Если цена идёт в сторону Big, текущий уровень должен завершаться полностью:

```text
Close Big = 100%
Close Small = 100%
```

Small нельзя оставлять открытым после Big-сценария.

Причина:

```text
Если Small не закрывать, они будут накапливаться на каждом уровне.
Это разрушает самосжатие системы и превращает её в многослойный лок.
```

После закрытия Big и Small считается чистая прибыль уровня:

```text
NetProfit = ProfitBig - LossSmall - Commission - SpreadCost - SlippageCost
```

Если комиссия, спред и проскальзывание не заданы, допускается упрощённая формула:

```text
NetProfit = ProfitBig - LossSmall
```

### 27.2. Главное правило закрытия дальнего хвоста

На закрытие самого дальнего хвоста можно использовать **не более 20% чистой прибыли уровня**:

```text
CloseFarBudget = NetProfit × 0.20
ReserveAdd = NetProfit × 0.80
```

Критически важное уточнение:

```text
20% — это не обязательно 20% лота хвоста.
20% — это денежный бюджет от чистой прибыли уровня.
```

Основной режим системы — **денежный**. Сначала система считает 20% чистой прибыли, затем определяет, сколько лота дальнего хвоста можно закрыть на этот денежный бюджет.

### 27.3. Режим 1: денежное закрытие хвоста

В денежном режиме фиксировано:

```text
20% чистой прибыли уровня
```

Формулы:

```text
CloseFarBudget = NetProfit × 0.20
CloseFarLot = CloseFarBudget / LossPerLotToClose
FarRemain = FarStart - CloseFarLot
```

Где:

```text
LossPerLotToClose = текущий убыток на 1 лот дальнего хвоста
```

Защита от ошибок:

```text
CloseFarLot = MIN(FarStart, MAX(0, CloseFarBudget / LossPerLotToClose))
```

Если `LossPerLotToClose <= 0`, деление запрещено: закрытие хвоста переводится в ручную проверку или хвост закрывается по отдельному правилу без использования этой формулы.

### 27.4. Режим 2: лотовое закрытие хвоста

В лотовом режиме цель — закрыть ровно 20% лота хвоста:

```text
TargetCloseFarLot = FarStart × 0.20
RequiredMoney = TargetCloseFarLot × LossPerLotToClose
```

Проверка:

```text
Если CloseFarBudget >= RequiredMoney:
    закрыть 20% лота хвоста
Иначе:
    закрыть только доступный объём по денежному бюджету
```

Лотовый режим не отменяет ограничение денежного бюджета. Даже если цель — закрыть 20% лота хвоста, нельзя тратить на это больше разрешённого бюджета `CloseFarBudget` без отдельного аварийного разрешения.

### 27.5. Уточнённый Small-сценарий

Если цена идёт в сторону Small, выполняются строго следующие действия:

```text
Close Small = 100%
Close Big = 22%
Remain Big = 78%
```

Формулы:

```text
CloseBigLot = BigLot × 0.22
RemainBigLot = BigLot × 0.78
```

Остаток Big становится новым дальним хвостом:

```text
NewFarStart = RemainBigLot
NewFarDirection = BigDirection
```

### 27.6. Обработка старого хвоста после Small-сценария

После Small-сценария система должна проверить старый хвост, потому что может появиться опасная структура:

```text
старый хвост ещё не закрыт
+
новый хвост из остатка Big
```

Правила обработки:

```text
Если старый хвост можно закрыть в плюс или в ноль:
    закрыть старый хвост полностью

Если старый хвост можно частично закрыть за счёт доступной прибыли:
    закрыть разрешённую часть

Если старый хвост остаётся в минусе:
    присвоить статус DUAL_TAIL / WARNING
    новый полноценный уровень запрещён без отдельного разрешения
```

При `DUAL_TAIL` система не имеет права автоматически открывать следующий полноценный уровень, потому что в рынке одновременно присутствуют старый хвост и новый хвост из остатка Big.

### 27.7. Статусы системы

| Статус | Значение |
| --- | --- |
| OK | Один хвост, резерв положительный, маржа в норме. |
| WARNING | Хвост уменьшается медленно, резерв мал, NetProfit не положительный или маржа почти не снижается. |
| DUAL_TAIL | Есть старый хвост и новый хвост одновременно. |
| DANGER | Растёт маржа, резерв отрицательный, хвост увеличивается или NetProfit сильно отрицательный. |
| STOP | Новые уровни запрещены. |

Новый уровень разрешён только если статус `OK` или явно разрешённый оператором `WARNING`. При `DUAL_TAIL`, `DANGER` или `STOP` автоматическое открытие нового полноценного уровня запрещено.

### 27.8. Строгие запреты v2

```text
1. Нельзя оставлять Small после Big-сценария.
2. Нельзя открывать новый уровень, если предыдущий уровень не закрыт.
3. Нельзя считать 20% прибыли равными 20% лота хвоста.
4. Нельзя открывать новый полноценный уровень при статусе DUAL_TAIL.
5. Нельзя использовать резерв для увеличения лота.
6. Нельзя открывать Big выше 120% от FarStart.
7. Нельзя открывать Small выше 45% от Big.
8. Нельзя закрывать меньше 22% Big при Small-сценарии.
9. Нельзя игнорировать спред, комиссию и проскальзывание.
```

### 27.9. Финальный алгоритм v2

```text
BIG_SIDE:
    Close Big = 100%
    Close Small = 100%
    NetProfit = ProfitBig - LossSmall - Costs
    CloseFarBudget = NetProfit × 20%
    ReserveAdd = NetProfit × 80%
    Основной режим закрытия хвоста = денежный

SMALL_SIDE:
    Close Small = 100%
    Close Big = 22%
    Remain Big = 78%
    Remain Big становится новым FarStart
    Старый хвост обязательно проверяется
    При DUAL_TAIL новый полноценный уровень запрещён
```

Система работает только при условии, что каждый уровень завершён. При Big-сценарии закрываются Big и Small. При Small-сценарии закрывается Small и 22% Big. Small не должен накапливаться. На дальний хвост используется максимум 20% чистой прибыли уровня. Основная защита системы — резерв 80%.

## 28. Главный вывод

Адаптивная самосжимающаяся система разруливания минусового замка — это не система агрессивного наращивания позиции, а система **управляемого сжатия риска**.

Её устойчивость появляется только при одновременном соблюдении всех ключевых правил:

- Big строится от текущего хвоста, а не от желания быстро отбить убыток;
- Small не накапливается;
- каждый уровень закрывается как завершённый цикл;
- хвост уменьшается в Big-сценарии;
- новый хвост уменьшается даже при Small-сценарии;
- резерв растёт быстрее, чем расходуется;
- маржа следующего цикла становится меньше;
- аварийные режимы запрещают дальнейшее раздувание.

Короткая формула философии системы:

```text
Не увеличить ставку, чтобы отбить минус,
а уменьшить минус так, чтобы следующий цикл был легче предыдущего.
```

# Синхронизация листов Excel

`Settings` является единственным источником истины для параметров workbook. Все расчётные листы обязаны брать коэффициенты, стоимость пункта, маржу, шаг лота, комиссии, спред и проскальзывание только из `Settings`.

`Calculator`, `Trend_UP` и `Trend_DOWN` обязаны иметь одинаковую структуру колонок и одинаковую логику формул. Если колонка добавлена на один расчётный лист, она должна быть добавлена на все три расчётных листа.

`Trend_UP` и `Trend_DOWN` отличаются только начальным направлением хвоста и преднастроенной последовательностью сценариев. Формулы Big, Small, CloseFar, Reserve, RealizedFarLoss, BLOCKED, DUAL_TAIL и ручного выхода должны оставаться одинаковыми.

`Risk_Analysis` обязан иметь отдельный блок `Calculator Summary` и отдельный блок `Global Risk Summary`. Блок `Global Risk Summary` должен считать одновременно `Calculator + Trend_UP + Trend_DOWN`.

Если `DUAL_TAIL` возникает на любом из расчётных листов, он должен отображаться в `Risk_Analysis`. При наличии `DUAL_TAIL` запрещено показывать нулевые значения `Max DualTail Exposure` и `Blocked Levels Count`, если в сценарных листах есть фактическая двуххвостовая экспозиция и BLOCKED-строки.

Workbook должен быть сохранён с автоматическим пересчётом формул: `calcMode = auto`, `fullCalcOnLoad = True`, `forceFullCalc = True`.

# Правило отсутствия циклических ссылок

Все строки калькулятора должны рассчитываться только от `Settings`, текущих входных данных и предыдущей строки. Формулы не должны ссылаться сами на себя напрямую или косвенно.

Разрешённый принцип расчёта:

```text
Row N = Settings + текущие входные данные Row N + состояние Row N-1
```

Запрещено:

```text
Row N -> Row N
Row N -> Row N+1
Row N -> Risk_Analysis -> Row N
```

`Risk_Analysis` не должен использоваться как источник данных для расчётных листов. Он является только итоговой аналитической витриной и обязан читать данные из `Calculator`, `Trend_UP` и `Trend_DOWN`, но не возвращать значения обратно в расчётные листы.
